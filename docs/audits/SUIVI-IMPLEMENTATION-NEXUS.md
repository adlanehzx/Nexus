## Preuves automatisées locales

- Dashboard : 223 tests passent après correction des vues d'accords, dossiers et coûts.
- MCP : 91 tests passent, dont une exécution bwrap réelle qui ne peut pas lire un secret hors montage.
- Documents : 13 tests passent ; VCS : 11 ; CLI : 81 hors test PostgreSQL optionnel.
- Outils : 64 tests passent, dont décision concurrente approuver/refuser avec un seul gagnant.
- Authentification PostgreSQL : créations concurrentes, rotation concurrente et rollback transactionnel testés sur une base jetable migrée.
- Sauvegarde : création chiffrée, vérification dans une base temporaire, restauration des données PostgreSQL et SQLite, configuration et secrets récupérés ; destination `.env` préservée.
- Moteur de missions : annulation idempotente, préservation des étapes réussies, invalidation du bail et redémarrage couverts.
- Monorepo : compilation réussie (37 tâches) ; suite globale réussie (3 304 tests, 65 tâches). La nouvelle régression de reprise réseau a ensuite été validée dans les 223 tests du dashboard.
- Types : 63 tâches réussies lors du premier passage global ; mobile et Windows worker arrêtés avec code 137 sous charge, puis réussis en relance séquentielle. Dashboard revalidé après correction de la classe d’erreur HTTP.
- Lint : tous les modules réussis après correction du dernier échec dashboard ; ce dernier a été revalidé séparément.
- Livraison : hygiène, câblage API (356 routes) et contrat worker passent. Les exceptions devenues inutiles pour checkpoints et confirmations ont été retirées de la liste de câblage.
- Carrière : 40 tests passent, dont le refus par défaut d'un envoi automatique sans adaptateur réel ; simulation injectée explicitement dans les tests.

Les tests API utilisent majoritairement des doubles de services externes. Ils ne constituent pas une validation fournisseur, appareil, réseau réel ou charge de production. Les tests PostgreSQL et sauvegarde utilisent exclusivement le conteneur jetable `nexus-plan-pg-test`, pas les données personnelles. Ce conteneur a été supprimé après la campagne.

## Contraintes restantes explicites

- Les fichiers de configuration des dossiers et confirmations ne sont pas des magasins multi-réplicas.
- Les outils MCP installés sous un répertoire utilisateur ont besoin de montages explicites du runtime et du paquet ; le dossier personnel hôte n'est plus implicitement lisible.
- L'arrêt d'une mission ne peut pas annuler un effet déjà accompli par un service externe.
- Le manifeste de sauvegarde ne couvre pas tous les fichiers de configuration, ni le coffre du système, ni une base PostgreSQL séparée du moteur de missions.
- La restauration en place exige l'arrêt des processus qui écrivent ; la recette exécutée est isolée.
- L’interface locale en service n’a pas été redéployée à ce stade. Le service systemd du moteur pointe vers une autre copie du dépôt : la compilation de cette branche ne met pas à jour ce service.
